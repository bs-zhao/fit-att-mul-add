# compare_noregen

Parallel classification pipeline to [../compare_regen](../compare_regen), without posterior regeneration.

- **s2_getmaxRT.py**: inspect RT / fixation-count percentiles in the original prior simulations generated by `../s1_gen1w.py` (the s2 script reports percentiles; as in compare_regen, it does not change `tools/maxT.py`).
- **s3_fe1_maxT.py**: load `outputs/food_equal/s1_gen1/<model>/gen1.pkl` ... `gen50.pkl` directly, apply the same `tools/maxT.py` fixed-length exclusions and produce `trialinfo`, `choice`, `rt`, `fsmr` for the classifier.
- **s4_train_classifier_maxT.py**: same `data2param` classifier, hyperparameters and architecture as `compare_regen`, trained on the prior-simulation features here.
- **s6_decode_maxT.py**: evaluate the classifier on the unchanged real-data features `outputs/food_equal/s3_fe1_maxT/real_data/fe.pkl`.
- **s6_decode_maxT_mr.py**: optional model recovery. Train with `s4_train_classifier_maxT.py` in the normal mode, then run `s3_fe1_maxT.py` with `for_test = 1` to prepare the independent original `s1_gen1_test` simulations. The recovery decoder loads the **real_data-trained** classifier and evaluates `compare_noregen/mr/trial/s3_fe1_maxT/<true_model>/gen1_batch0.pkl`.
- **train.sbatch**: submits `s4_train_classifier_maxT.py` from this directory.

All classifier outputs are isolated under `outputs/food_equal/compare_noregen/`. **Nothing is regenerated or written into `outputs/food_equal/compare_regen/`.**

From `run/fit_nn/food_equal/compare_noregen`, run:

```bash
python s2_getmaxRT.py
python s3_fe1_maxT.py
sbatch train.sbatch
python s6_decode_maxT.py
```

**Important:** The `model_names` lists in `s3`, `s4` and `s6` must cover the same desired models; adjust them together when switching from 2 to 4 or 8 models. The original simulations must already exist in `outputs/food_equal/s1_gen1/`; missing `gen*.pkl` files are skipped in `s3`. For `for_test = 1`, the source is `outputs/food_equal/s1_gen1_test/` and only `gen1.pkl` is read.

Unlike the posterior-regeneration comparison, this workflow uses parameter draws from the simulation priors defined in `../tools/model_info.py`; the posterior-regeneration workflow draws model parameters from fitted real-data decoder estimates.
